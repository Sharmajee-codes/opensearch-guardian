# Contributing to OpenSearch Guardian

Thank you for your interest in contributing to OpenSearch Guardian! We welcome contributions from the community.

## How to Contribute

1. **Issue First**: Before starting work, please open an issue describing the proposed change or bug fix. This allows maintainers to review and discuss the approach.

2. **Fork and Branch**: Fork the repository and create a new branch for your changes.

3. **Pull Request Workflow**:
   - Make your changes in your fork
   - Ensure your code follows the project's coding standards
   - Add or update tests as appropriate
   - Open a pull request against the main branch
   - Provide a clear description of your changes in the PR template
   - Respond to reviewer feedback promptly

## Testing Expectations

All contributions should include appropriate tests following the project's testing strategy:

- **Unit Tests**: Test individual functions and components in isolation
- **Integration Tests**: Test interactions between components
- **Fixture Tests**: Test with predefined data sets to ensure consistency
- **End-to-End (E2E) Tests**: Test complete user workflows

Refer to the `tests/` directory for examples of existing tests.

## Code of Conduct

Please note that this project is released with a Contributor Code of Conduct. By participating in this project you agree to abide by its terms. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) for details.

Security issues should be reported privately as described in [SECURITY.md](SECURITY.md). Do not open public issues for security vulnerabilities.
