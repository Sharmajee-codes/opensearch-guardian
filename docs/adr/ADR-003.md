# ADR-003: Technology Stack

**Status:** Accepted
**Date:** 2026-08-19
**Decided by:** Phyllis (T4), reviewed by god

## Context

OpenSearch Guardian is a cross-platform desktop operations console that must integrate with OpenSearch REST APIs, optional Docker Engine API, optional Kubernetes API, and optionally an LLM provider for explanation. The SOP defines a layered architecture (SOP §4) and a recommended technology stack (SOP §4.1). The stack must support IPC isolation between the Electron renderer and the backend core, strong typing, and a rich infrastructure ecosystem.

## Decision

The project uses the following stack:

| Layer | Technology | Rationale |
|---|---|---|
| Desktop UI | Electron + React + TypeScript | Cross-platform operator console; React provides component model; TypeScript enforces type safety. |
| Core / API | Python 3.12+ with FastAPI and Pydantic | Strong infrastructure and data-tooling ecosystem; FastAPI gives async support and automatic OpenAPI docs; Pydantic validates all connection and diagnosis models. |
| OpenSearch integration | opensearch-py + REST adapters | Official-style Python integration; adapters normalize responses into stable internal models. |
| CLI | Typer + Rich | Headless and server workflows; Rich provides formatted terminal output. |
| Local persistence | SQLite | Zero-setup history and config metadata; single-file database for the desktop app. |
| Production history (optional) | PostgreSQL | Multi-user or server mode; backfills the optional multi-tenant path. |
| Streaming UI | WebSocket or SSE | Pushes normalized snapshots and events to the Electron renderer. |
| Container integration | Docker Engine API (not shell parsing) | Avoids fragile `docker ps`/`docker inspect` string parsing. |
| Kubernetes integration | Official Kubernetes client (`kubernetes` Python package) | Native resource, RBAC, and watch support. |

The Electron renderer must never contain cluster administrator credentials or execute arbitrary shell commands (SOP §4). A restricted IPC/API boundary separates the renderer from the Guardian Core service.

## Consequences

**Positive:**
- TypeScript in the renderer and Python in the core give strong typing on both sides of the IPC boundary.
- FastAPI auto-generates OpenAPI specs, aiding CLI and future API consumers.
- SQLite eliminates external database setup for the default desktop experience.
- Docker Engine API and the official K8s client avoid shell-parsing fragility.
- opensearch-py is the community-standard Python client, ensuring up-to-date API coverage.

**Negative:**
- Two language runtimes (Electron/Node.js + Python) increase build and distribution complexity.
- Electron bundle size is larger than native alternatives.
- Python packaging for distributable desktop apps (PyInstaller, Nuitka) adds release engineering overhead.
- WebSocket/SSE streaming requires the Python core to maintain long-lived connections.

**Mitigations:**
- A documented developer environment using Docker Compose (SOP §9) reproduces the full stack locally.
- The IPC boundary is a first-class module, not an afterthought.
- Build scripts and CI pipelines automate the Python → bundled executable path.
