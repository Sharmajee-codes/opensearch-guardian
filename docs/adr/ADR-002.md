# ADR-002: Read-Only by Default; Write/Provisioning Gated Per-Connection

**Status:** Accepted
**Date:** 2026-08-19
**Decided by:** Phyllis (T4), reviewed by god

## Context

OpenSearch Guardian interacts with production search clusters that may hold critical data. The SOP mandates that the default connection mode must be read-only (SOP §8) and that write or provisioning privileges be explicitly enabled per connection. The risk surface includes accidental index deletion, uncontrolled node scaling, and credential leakage.

## Decision

Every connection profile starts in read-only mode. Write, provisioning, and remediation permissions are gated behind an explicit per-connection enablement flow. Monitoring permissions and provisioning permissions are managed as separate permission sets within the same connection profile. Credentials are stored in the OS keychain, never in plaintext configuration files. TLS verification is enabled by default.

## Consequences

**Positive:**
- Reduces risk of accidental data loss or cluster disruption.
- Aligns with least-privilege security principles.
- Users cannot trigger provisioning without explicit consent for that connection.
- Audit trail can clearly distinguish read-only monitoring actions from write operations.

**Negative:**
- Users who want full functionality must complete an additional permission-granting flow.
- Development and testing workflows need deliberate permission configuration.
- Dual permission sets (monitoring vs. provisioning) add complexity to the connection profile model.

**Mitigations:**
- The connection test (SOP §3.1) reports permission level explicitly.
- The UI surfaces a clear "write access: disabled" indicator on read-only connections.
- The approval workflow (SOP §7, step 6) requires explicit user confirmation before any infrastructure write.
