# ADR-005: Tiered Adaptive Collection Cadence with Normalized Internal Models

**Status:** Accepted
**Date:** 2026-08-19
**Decided by:** Phyllis (T4), reviewed by god

## Context

OpenSearch clusters expose a wide range of APIs with varying cost: cluster health is cheap and frequent; mapping scans and allocation-explain calls are expensive and infrequent. Connecting directly to the raw OpenSearch API responses would couple diagnostic rules and optimizer logic to specific OpenSearch versions, causing breakage on upgrades. The SOP calls for adaptive polling cadences and normalized internal models.

## Decision

The Guardian Core service implements a tiered collection strategy that normalizes all API responses into stable internal models before any rules or optimizers consume them:

| Cadence | Signals | Purpose |
|---|---|---|
| ~5 s | Cluster health, lightweight status | Live UI overview, alert triggering |
| ~10–15 s | Selected node metrics, shard state | Trending, Doctor rule evaluation |
| ~30–60 s | Index/storage statistics, recoveries | Cost optimizer, capacity planner |
| ~5 min | Expensive diagnostic/cost analyses, mappings, policies, deeper scans | Proactive optimization recommendations |
| On-demand | Allocation explain, targeted index/node diagnostics, pre/post provisioning verification | User-initiated deep dives |

Collectors transform raw OpenSearch API responses (which vary by version) into version-agnostic internal models. Rules and optimizers operate on these models, not on raw API responses. During incidents, the collector enters adaptive mode: cheap signals increase in frequency, and expensive diagnostics are deferred until the incident stabilizes.

## Consequences

**Positive:**
- Rules and optimizers are decoupled from OpenSearch version details.
- API call volume is bounded and predictable under normal operation.
- Adaptive cadence reduces overhead during stable periods and increases responsiveness during incidents.
- On-demand deep dives give operators control without constant expensive polling.

**Negative:**
- The normalization layer adds code complexity and must be maintained as OpenSearch APIs evolve.
- Adaptive cadence logic adds state management overhead to the collector.
- The 5-second minimum poll interval may miss very short-lived anomalies.

**Mitigations:**
- The `collectors/` module has a clear contract: raw response in, normalized model out.
- Fixtures cover multiple OpenSearch versions to catch normalization regressions.
- The adaptive cadence is driven by observable incident signals (e.g., health transition to red), not heuristics.
